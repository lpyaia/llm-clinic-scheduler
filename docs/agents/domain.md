# Domain docs

This is a single-context repository. Domain vocabulary belongs in a root `GLOSSARY.md`; architecture decisions belong in `docs/adr/`.

Before exploring, read the glossary if present and any ADRs relevant to the work. Use glossary terms in tickets, code and tests. Flag an actual conflict with an existing ADR before proposing a different decision.

If these documents do not exist, proceed silently. Do not create placeholder glossaries or ADRs during setup; domain modeling creates them when terms or decisions are resolved.

Read the product requirements and the approved development plan for product scope and established implementation decisions.
